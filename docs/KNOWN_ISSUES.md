### 測定条件(T1〜T16)
- 実際の JUCE 8.0.4 の `juce_core` / `juce_audio_basics` / `juce_dsp` にリンクして、このリポジトリの DSP をそのまま実行(gcc -O2, Linux)。GUI 部分は含みません。

- **CPU 使用率はこのコンテナでの参考値**(MSVC / お使いの PC とは異なる)。

## 2. 比較について(重要)
Logic Pro と Cubase Pro の標準コンプレッサーとの**比較は一切行っていません**。仕様の求める「ラウドネスマッチングしたブラインド試聴」と「同一素材での測定」は、実機の DAW と人間の耳が必要で、この環境ではできないためです。したがって**「それらを超えた」とは主張できません**。比較したい場合は、
1. 同じボーカル素材を用意し、各コンプレッサーのゲインリダクション量がほぼ同じになるよう設定、
2. 出力を LUFS(または RMS)で合わせ、
3. 誰が処理したか分からない状態で聴き比べる、
という手順で行ってください。

## 3. 既知の制約・注意
1. **レイテンシー通知**: Lookahead / OS を変えたときのレイテンシー再申告は、非同期(メッセージスレッド)で `setLatencySamples` を呼びます。ホストによっては再生を止めて再開するまで反映されない場合があります(未確認)。
2. **Oversampling は FET / Vari-Mu のみ有効**。他のモデルでは遅延が増えるだけです(モデル切替で遅延を変えないための仕様)。
3. **IIR 半帯域フィルターは線形位相ではない**。OS 使用時の位相は周波数でずれます(T6)。
4. **FET / Vari-Mu は DC ブロッカー**(約 3 Hz)を持つため、20 Hz で -0.1 dB・位相 +8.5° の変化があります(T6)。Transparent / Opto / VCA は 20 Hz〜0.45 fs で振幅・位相とも誤差 0。
5. **Auto Makeup** は、-12 dBFS の信号に対する静的 GR を補う簡易方式です(ラウドネス自動合わせではない)。圧縮の深さ・素材により聴感上の音量は変わります。
6. **ボーカル機能のしきい値は固定のヒューリスティック**です。男性/女性、ささやき、ラップなど素材により、誤検出(例: 低い声の基音を破裂音と誤認)の可能性があります(未確認)。
7. **Attack / Release 表示は理想的な 1 次系**の曲線で、モデル別の特性(Opto の履歴依存、VCA の直線リリースなど)は描いていません。数値は測定結果(T3)を参照。
8. **Release の実測値は設定より約 10 % 長い**(2 段スムージング)。Attack は一致します。
9. メーターの RMS は dB 領域の簡易平滑(約 300 ms)で、ITU / EBU 準拠のメーターではありません。
10. 最大 2 チャンネル(モノ・ステレオ)。サラウンド非対応。VST2 / AU / AAX は非対応(VST2 はライセンス上の理由で作らない)。
11. Undo / Redo は JUCE の UndoManager(パラメーター変更の履歴)を使います。プリセット読込・A/B 切替・初期化は 1 回分としてまとめます。1 回の記録単位はホストの操作(ドラッグ等)の通知方法に依存します(未確認)。プロジェクトを読み込むと履歴は空になります。
12. ユーザープリセットは `%APPDATA%\VocalCompressor\Presets`。同名で保存すると確認なしで上書きします。
13. Windows 以外(macOS / Linux)でのビルドは想定していません(未確認)。
14. JUCE のライセンス(AGPLv3 / 商用)に従ってください。
